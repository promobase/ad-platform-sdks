The OpenPromo SDK family gives you provider-native clients, generated low-level contracts, and a
cross-platform operation catalog from the same packages. Start with the umbrella package unless you
only ship one integration.

## Install

```bash
bun add @mosaic/ad-platforms
```

Individual packages such as `@mosaic/meta`, `@mosaic/tiktok`, and `@mosaic/youtube` are
available when bundle isolation matters.

## Create clients

```ts
import { Meta, TikTok } from "@mosaic/ad-platforms";
import { YouTube } from "@mosaic/ad-platforms/youtube";

const meta = Meta.createClient({ accessToken: process.env.META_TOKEN! });
const instagram = Meta.Instagram.createClient({
  api: meta,
  igAccountId: "ig_123",
});

const tiktok = TikTok.createClient({
  accessToken: process.env.TIKTOK_TOKEN!,
  businessId: "business_123",
});

const youtube = YouTube.createClient({
  accessToken: process.env.YOUTUBE_TOKEN!,
});
```

Pass credentials from your application at runtime. Do not bake access or refresh tokens into a
bundle, repository, or generated configuration.

## Choose the right layer

| Need | Use |
| --- | --- |
| Provider-specific breadth | A platform client or generated Effect entrypoint |
| Portable post metrics and agent actions | `@mosaic/ad-platforms/operations` |
| AI SDK tools | `@mosaic/ad-platforms/operations/ai` |
| Code Mode connector definitions | `@mosaic/ad-platforms/operations/codemode` |
| Terminal or MCP access | `@mosaic/ad-platforms-cli` |

Continue with [authentication](/guides/authentication), then choose the [Promise and Effect
runtime](/guides/promise-and-effect) or [operation catalog](/guides/agent-surfaces).
