The SDKs own provider protocol mechanics: authentication inputs, request/response contracts,
pagination, retry classification, rate-limit signals, provider-native publishing primitives,
provider-native inbox primitives, and normalized post metrics.

OpenPromo—or any product built on the SDKs—should own the durable control plane:

- encrypted workspace credentials and refresh-token rotation;
- connection lifecycle and account selection;
- approvals, policy, budgets, billing, and audit logs;
- durable retries, idempotency records, scheduling, and operation polling;
- persistence of posts, conversations, raw metrics, and normalized reporting data.

Adopt read-only account, content, inbox, and metrics calls first and compare stored provider
fixtures. Migrate writes after idempotency and reconciliation are proven. Keep provider payloads
alongside normalized records so new fields can be backfilled without re-fetching historical data.

For generated TypeScript, Valibot, and Effect contracts, see [Generated contracts](/guides/generated-contracts).
For webhook verification and event extraction, see [Meta webhooks](/guides/webhooks). For durable
external effects, see [Publishing and workflows](/guides/publishing-and-workflows). The complete
OAuth-to-webhook composition is shown in [End-to-end examples](/guides/end-to-end-examples).
